## 4. 라우팅 구조

- HashRouter 사용 (클라이언트 사이드 라우팅)
- Layout 컴포넌트로 사이드바 + 헤더 공유
- 기본 경로 → 대시보드 리다이렉트
- 인쇄 페이지는 Layout 없이 독립 렌더링

## 5. 데이터 저장 방식

- **로컬 저장**: localStorage (JSON 직렬화)
- **서버 저장**: Supabase (PostgreSQL + anonymous auth)
- **동기화**: 30초마다 + 포커스 시 자동 동기화
- **P8 엔트리**: report_comments 테이블에 JSON으로 직렬화 저장 (Supabase 제약 조건 회피)
- **생산량집계**: report_comments 테이블에 JSON으로 직렬화 저장

## 6. API/백엔드 구조

- Supabase REST API (PostgREST) 사용
- 테이블: users, production_reports, production_entries, equipment_targets, production_period_targets, report_comments
- 익명 인증 (signInAnonymously)
- 수동 페이지네이션 (1000건 단위 fetchAll)

## 7. 인증/권한 구조

- 실제 인증 없음 (드롭다운으로 사용자 전환)
- 역할: admin, manager, user, viewer
- 권한 플래그: can_write, can_edit, can_delete
- admin은 모든 권한 자동 부여

## 8. 상태관리 방식

- Zustand 단일 스토어 (reportStore)
- localStorage → Supabase 순차 하이드레이션
- 원격 쓰기 큐 (serial promise chain)로 동시성 제어
- PersistedReportState 인터페이스로 전체 상태 직렬화

## 9. 배포 방식

- Vercel 배포 (vercel.json 존재)
- Vite 빌드 → dist 폴더
- SPA (싱글페이지 앱)

## 13. 사용자 경험상 불편한 부분

| 항목 | 설명 |
|------|------|
| 로딩 상태 | 데이터 로딩 중 스켈레톤이나 스피너 없음 |
| 빈 화면 처리 | "보고서가 없습니다" 텍스트만 노출 |
| 에러 메시지 | 기술적 JSON.stringify 노출 (persistence.ts:389) |
| 모바일 테이블 | 가로 스크롤이 필요한 복잡한 테이블 |
| 반응형 | 사이드바 토글은 있으나 모바일 전용 레이아웃 없음 |
| 키보드 네비게이션 | 일부 커스텀 셀렉트/버튼에서 부족 |
| 자동 저장 알림 | 저장 완료 시 2초간 텍스트 변경으로만 알림 |

## 14. 코드 품질상 개선이 필요한 부분

| 항목 | 설명 |
|------|------|
| 중복 계산 | calcNullableRate, getRateClass 등이 여러 파일에 중복 정의 |
| `as any` 사용 | TypeScript 타입 안전성 저해 |
| 큰 컴포넌트 | DashboardPage.tsx 1200줄+, UserInputPage.tsx 981줄 |
| CSS 인쇄 규칙 | index.css의 @media print 블록이 700줄 이상 |
| React Query 미사용 | 의존성에 추가되었으나 실제로 Zustand에서 직접 관리 |
| `setTimeout` 패턴 | 자동 사라지는 알림에 setTimeout 사용 (메모리 누수 가능) |
| 엑셀 XML 수동 조작 | JSZip + DOMParser로 수동 XML 생성 (복잡성 높음) |
